# Command Center 3.0 Migration Map

长期目标、未完成项、优先级和验收标准集中维护在
[`docs/command_center_3_long_term_goals.md`](command_center_3_long_term_goals.md)。
本文件只描述现有模块到 3.0 API/UI 的迁移映射，不把 scaffold / preflight / mock / sanitizer 误写为 production complete。

## Legacy Bug / UX Audit Seed

迁移图现在先执行“能力保留，不复制旧 Streamlit”的审计口径。下表是普通工作流的初始分类种子，来源于 `app.py` 的 legacy tabs、`server/services/legacy_service.py` 的 primary workflow route inventory，以及当前 React route 覆盖状态；它不是完成审计，也不是生产验收证据。后续任何旧模块进入普通用户路径前，都必须把该行补成直接 UX/bug evidence，并说明保留了什么能力、去掉了什么旧 UX 问题、没有迁移哪条历史 patchwork 路径。

`GET /api/legacy/cache` 现在还只读输出 `legacy_bug_ux_module_rows`，把下表模块分类同步到 Legacy/Admin/Debug 页面；该输出不打开 Streamlit、不创建任务、不调用 provider/model，也不代表任何旧模块已通过生产迁移验收。

Legacy Bug / UX Audit 的覆盖锁定为普通旧工作流组，而不是旧文件名或旧 tab 数量：home/daily command、searched-symbol quant projection、candidate radar、next-session map、factor/risk/provider health、discipline/backtest、ETF/leverage、external brain/AI advisor 都必须有行级判断。每行至少保留 `direct UX/bug evidence source`、`ordinary entrance placement` 和 `frozen legacy path` 三个证据槽；缺少直接 UX/bug evidence 的模块不能从 route inventory、legacy tab name、本地 receipt 或 no-feature-loss matrix 直接升级为 `KEEP`，只能保持 `REDESIGN`、`LEGACY-DEBUG` 或 `RETIRE`。

`KEEP` 提升门槛必须是直接审计证据，而不是 seed-only 清单：审计行要写清 observed user action / workflow problem、被移除的 legacy bug / confusing UX / patchwork path、data-lineage check、replacement ordinary entrance 和 frozen legacy path；docs/config/scaffold、本地 receipt、route inventory 或 no-feature-loss matrix 只能作为参考，不能单独把旧模块升级为 `KEEP`。

`COMMAND_CENTER_LEGACY_AUDIT_CLASSIFICATION_CONTRACT` / `get_command_center_legacy_audit_classification_contract()` 是 Legacy Bug / UX Audit 分类词表的配置层合同：`KEEP` 必须遵守 `keep_requires_direct_legacy_bug_ux_audit_evidence`，seed-only 清单必须遵守 `seed_inventory_receipt_matrix_or_docs_config_cannot_promote_keep`，进入普通入口前必须满足 `ordinary_entry_requires_replacement_entrance_and_frozen_legacy_path`。该合同仍是 `legacy_audit_classification_contract_is_not_production_evidence`，只用于阻止盲迁旧 UI/code，不是生产验收。

同一合同现在也固定直接证据状态门槛：`direct_evidence_row_required_before_keep_or_ordinary_entry`、`seed_only_rows_default_to_redesign_legacy_debug_or_retire`、`unclear_data_lineage_blocks_ordinary_entry_until_redesigned_or_frozen`、`audit_scope_tracks_workflow_group_not_legacy_file_or_tab_count`。审计行只有补齐直接证据后才能进入 `direct_evidence_ready`；一旦是 `blocked_by_lineage`，就必须先重设 lineage 或冻结旧路径。`route_inventory_only`、`legacy_tab_name_only`、`docs_config_scaffold_only`、`local_receipt_only`、`no_feature_loss_matrix_only`、`mock_sanitizer_or_preflight_only` 都不能把旧模块升级为 `KEEP`。

Legacy Audit 行级证据还必须满足 `legacy_audit_row_requires_scope_status_direct_source_lineage_replacement_and_freeze_decision`：每个旧普通工作流行必须包含 `workflow_group`、`legacy_surface_or_module`、`observed_user_action_or_workflow_problem`、`direct_ux_bug_evidence_source`、`classification`、`evidence_status`、`data_lineage_check`、`replacement_ordinary_entrance`、`frozen_legacy_path`、`ordinary_entry_decision` 和 `next_action`。`file_inventory_only`、`legacy_tab_count_only`、`route_exists_only`、`local_receipt_only`、`docs_config_scaffold_only` 或 `no_feature_loss_matrix_only` 不能让审计行完成。

Legacy Audit seed rows 由 `legacy_audit_seed_rows_cover_ordinary_workflow_scope_without_keep_promotion` 固定，且必须保持 `legacy_audit_seed_rows_are_not_direct_evidence_or_production_evidence`。当前 seed 覆盖 `streamlit_home_daily_summary`、`legacy_single_stock_room_quant_projection`、`legacy_candidate_radar`、`legacy_next_session_chart`、`legacy_factor_risk_provider_health_tables`、`legacy_discipline_backtest_lab`、`legacy_margin_etf_leverage_flow` 和 `legacy_external_brain_ai_advisor`；这些行只能是 `not_promoted_seed_only`、`not_promoted_legacy_debug` 或 `not_promoted_retire`，直到补齐直接 UX/bug evidence。

第一轮 Legacy Bug / UX Audit 的直接取证模板只用于把 seed row 推进到“可审计问题陈述”，不是新 contract、receipt、matrix 或 production evidence。每个旧普通工作流在进入普通入口前，必须先填这 7 个槽位：`user_observation`（用户真实操作或卡住的位置）、`legacy_ux_bug_or_patchwork`（旧 UX 问题、bug 或历史补丁路径）、`data_lineage_observation`（数据来源、缓存、provider/model 边界是否清楚）、`replacement_user_path`（对应的新 3.0 普通入口和下一步点击）、`frozen_legacy_path`（明确冻结的旧路径）、`evidence_attachment`（截图、录屏、日志摘要或人工复核记录的安全引用）、`keep_promotion_decision`（本轮必须是 `no_keep_promotion_this_round`，除非直接证据已完整且另行评审）。这个模板不要求打开 Streamlit、不调用 Tushare/DeepSeek/GitHub、不创建 task、不读取 token/key，也不能把 route inventory、本地 receipt、no-feature-loss matrix、mock、sanitizer 或 docs/config scaffold 当作直接 UX/bug evidence。

第一轮取证的输出只能把行状态推进为 `direct_evidence_intake_pending`、`direct_evidence_observed_redesign_required`、`blocked_by_lineage`、`legacy_debug_retained` 或 `retire_confirmed`。`KEEP` 仍然保持禁止，直到同一行同时具备完整直接证据、明确 replacement ordinary entrance、冻结旧路径、数据血缘复核和后续验收计划；即便满足这些条件，也必须在独立 checkpoint 中说明为什么普通用户会更简单、更可靠，并且不能把本轮取证当作生产验收。

第一轮直接取证工作清单先覆盖当前优先级最高的普通工作流：home/daily command、searched-symbol quant projection、candidate radar；并补 next-session map、factor/risk/provider health、hard risk / announcement risk、discipline/backtest、ETF/leverage、external brain / Serenity / Chokepoint 与 old AI strategy advisor / cross-market advice button 依赖工作流取证 row，避免后续 ECharts/operation zones、provider-health 明细、硬风险摘要、回测复盘实验室、杠杆/ETF 风险预算、外脑/RAG/probe 数据 lineage 或 AI-as-action 跨市场事实迁移绕过 Legacy Bug / UX Audit。它的用途是把下一次人工复核或截图/录屏复核该看哪里写清楚，不是新合同、不是 receipt、不是 production evidence，也不会把任何 seed row 升级成 `KEEP`。

### Ordinary Entrance Acceptance Map

这张表是 Legacy Bug / UX Audit 的入口级补充：它不新增 contract、receipt 或 production evidence，只规定旧能力进入普通用户 3.0 首页前必须回答什么。每个入口都必须把工程审计细节藏到 Settings / Developer / Audit，普通页只保留能帮助用户下一步判断的状态。

`COMMAND_CENTER_ORDINARY_AUDIT_PLACEMENT_CONTRACT` / `get_command_center_ordinary_audit_placement_contract()` 是普通入口审计降噪的配置层合同：三入口必须遵守 `ordinary_pages_show_user_summary_before_engineering_audit_details`，工程明细必须按 `detailed_engineering_audit_tables_move_to_settings_developer_audit` 后置，且 `engineering_contract_tables_must_not_dominate_ordinary_pages`。该展示规则必须保持 `audit_placement_display_never_creates_tasks`，并且仍是 `ordinary_audit_placement_contract_is_not_production_evidence`。

普通入口升级还必须满足 `ordinary_entry_promotion_requires_user_summary_fields_before_engineering_detail` 和 `ordinary_first_view_shows_next_click_state_gaps_boundary_and_last_success_before_audit`。首屏证据至少包括 `next_click_visible_before_audit_detail`、`source_state_visible_before_audit_detail`、`missing_evidence_visible_before_audit_detail`、`research_only_boundary_visible_before_audit_detail`、`last_successful_cache_or_result_visible_before_audit_detail`、`settings_developer_audit_link_visible_for_details`；`engineering_contract_table_as_primary_surface`、`receipt_rows_as_primary_surface`、`legacy_route_inventory_as_primary_surface` 不能成为普通用户主表面。

工程审计退场还必须满足 `ordinary_first_view_must_not_be_engineering_audit_dashboard`：`ordinary_summary_rendered_before_any_engineering_table`、`engineering_contract_tables_demoted_to_settings_developer_audit`、`receipt_rows_demoted_to_settings_developer_audit`、`runbooks_demoted_to_settings_developer_audit`、`ltg_audit_surfaces_demoted_to_settings_developer_audit`、`current_decision_surface_exception_reason_visible_when_detail_stays`，以及 `settings_developer_audit_link_visible_after_summary`。`audit_table_before_user_summary`、`receipt_rows_before_next_click`、`runbook_before_source_state`、`ltg_audit_as_default_page_body`、`all_details_hidden_without_audit_link`、`local_receipt_only` 或 `docs_config_scaffold_only` 不能算普通页已经降噪。

普通入口任务边界也必须留在用户摘要区，而不是藏进工程审计表：`今日作战台 / Daily Command Center`、`股票量化推演 / Stock Quant Projection`、`下一票雷达 / Candidate Radar` 都要在 Settings / Developer / Audit 细节之前显示 `任务边界`。该边界必须说明 `GET cache` / React render 只读，`manual` 或 `live_light` 补证只能走 `POST task` / worker / local fallback，不在页面渲染中直连 Tushare、DeepSeek 或交易路径；这条规则是 UI 迁移口径，不是 production evidence，也不等于完整 `live_light` 已实现。

三入口的普通用户摘要必须共享 source-state chips：`cache`、`Tushare`、`DeepSeek`、`pending`、`degraded`、`last_successful_cache/result`。`cache` 表示本地 packet/cache 来源，`Tushare` 表示 provider-backed 或 provider-pending 市场数据并带 call-ledger 状态，`DeepSeek` 只表示 explanation-only 且不是数据源或 action writer，`pending` 表示缺失/未跑/等待证据，`degraded` 表示 stale/failed/partial source 并显示 blocker，`last_successful_cache/result` 表示可回退的最近安全结果。这些 chips 只是只读 UI 词表，不创建 task、不调用 provider/model、不写 cache/config，也不是 production evidence。

`COMMAND_CENTER_ORDINARY_SOURCE_STATE_CONTRACT` / `get_command_center_ordinary_source_state_contract()` 是这组 source-state chips 的配置层合同：普通摘要必须按 `read_only_source_state_chips_in_ordinary_summary` 展示，`Tushare` 只能表示 `provider_backed_or_provider_pending_market_data_with_call_ledger_status`，`DeepSeek` 只能表示 `explanation_only_model_output_never_data_source_or_action_writer`，`pending/degraded` 必须遵守 `pending_or_degraded_state_must_show_missing_evidence_or_blocker`。这些 chips 必须保持 `source_state_chips_never_create_tasks`、`source_state_chips_never_write_cache_or_config` 和 `source_state_contract_is_not_provider_model_or_production_evidence`。

`COMMAND_CENTER_ORDINARY_SOURCE_STATE_DISPLAY_CONTRACT` / `get_command_center_ordinary_source_state_display_contract()` 是三入口 source-state 字段展示合同：普通摘要必须满足 `provider_model_cache_pending_states_must_be_visible_in_ordinary_summary`，Tushare 状态必须是 `tushare_state_requires_call_ledger_or_provider_pending_marker`，DeepSeek 状态必须是 `deepseek_state_is_explanation_only_with_model_ledger_or_pending_marker`，cache 状态必须遵守 `cache_state_must_show_freshness_and_last_successful_pointer`，pending 状态必须按 `pending_state_must_name_missing_evidence_or_next_allowed_task` 说明缺口或下一步。该展示仍保持 `ordinary_source_state_display_never_creates_tasks`，并且是 `ordinary_source_state_display_contract_is_not_provider_model_or_production_evidence`。

普通页面上的 provider/model/cache/pending 状态可见性必须满足 `ordinary_source_state_page_visibility_requires_provider_model_cache_pending_last_successful_and_blocker_rows`：`source_state_visible_in_ordinary_summary`、`cache_freshness_and_last_successful_pointer_visible`、`tushare_call_ledger_or_provider_pending_marker_visible`、`deepseek_model_ledger_or_pending_marker_visible`、`pending_missing_evidence_or_next_allowed_task_visible`、`degraded_blocker_and_safe_fallback_visible`、`no_trade_no_action_boundary_visible_next_to_state`，以及 `settings_developer_audit_link_for_detail_visible`。`ordinary_source_state_cannot_promote_from_hidden_tabs_tooltips_or_engineering_tables_only` 阻止 `engineering_audit_table_only`、`settings_detail_only`、`tooltip_only`、`hidden_tab_only`、`local_receipt_only` 或 `docs_config_scaffold_only` 被当成普通页面清晰度证据。

三入口还必须共享 next-click 规则：每个普通入口只突出一个主下一步动作，并在 blocked/degraded 时显示为什么不能点。`今日作战台 / Daily Command Center` 指向查看今日 cache/决策摘要或查看缺失证据；`股票量化推演 / Stock Quant Projection` 从已确认代码指向 `生成 3.0 量化推演`；`下一票雷达 / Candidate Radar` 指向查看 last radar cache 或按钮门控的 quick scan 创建/复用。搜索输入、React render、mode banner、source-state chip、DeepSeek 文本和 radar candidate 都不是 next-click action；任何会创建工作的 next click 都必须走 POST task / worker / local fallback，并显示 task status 与 no-trade/no-action 边界。

`COMMAND_CENTER_ORDINARY_NEXT_CLICK_CONTRACT` / `get_command_center_ordinary_next_click_contract()` 是三入口 next-click 的配置层合同：每个入口遵守 `one_primary_safe_action_per_ordinary_entrance`，blocked/degraded 时必须有 `disabled_or_degraded_reason_visible_before_click`，会创建工作的点击必须走 `work_creating_next_click_must_use_post_task_worker_or_local_fallback` 并显示 `work_creating_next_click_must_show_task_status`。搜索输入、React render、mode banner、source-state chip、DeepSeek text 和 radar candidate 继续只是非动作面；合同还固定 `next_click_is_research_only_no_buy_sell_instruction` 与 `ordinary_next_click_contract_is_not_execution_or_production_evidence`。

`COMMAND_CENTER_ORDINARY_RESEARCH_BOUNDARY_CONTRACT` / `get_command_center_ordinary_research_boundary_contract()` 是三入口 research-only 边界的配置层合同：普通摘要必须显示 `research_only_not_buy_sell_instruction` / `show_research_only_boundary_in_ordinary_summary`，DeepSeek 文本只能是 `deepseek_text_is_explanation_only_not_data_source_or_action`，factor 分数只能是 `factor_scores_are_research_evidence_not_trade_action`，Next Session `operation_zones` 只能是 `operation_zones_are_conditions_not_orders`。所有普通输出必须遵守 `never_modify_strategy_action_prices_positions_factors_or_operation_zones`，该合同仍是 `research_boundary_contract_is_not_execution_or_production_evidence`。
